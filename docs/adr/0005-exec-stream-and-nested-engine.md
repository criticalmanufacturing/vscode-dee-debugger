# ADR 0005 — Stream files over exec stdin/stdout; engine command is a configurable prefix

Status: accepted (2026-08-14). Supersedes the transport part of ADR 0004.

## Context
First smoke test hit the standard CM devcontainer topology: the MES stack runs in
**docker-in-docker** inside the project devcontainer. The host container (`custom_host` in
cmf-cli scaffolded stacks) is only reachable via `docker exec <devcontainer> docker …`, and the
extension host's local filesystem is invisible to that inner engine — so `docker cp <localfile>`
cannot work there. Additionally, the MES host image (RHEL 8 based) ships **no curl or wget**, so
"download vsdbg inside the container" fails.

## Decision
1. `HostTarget.engineCommand` (setting `deeDebugger.host.engineCommand`): a command prefix for
   reaching the engine that runs the host — default `docker`/`kubectl`, nested form e.g.
   `["docker","exec","-i","<devcontainer>","docker"]`. Every container operation (file bridge,
   vsdbg probe/install, coreclr `pipeTransport`) is built from this prefix in
   `src/core/hostExec.ts` (pure, unit-tested argv builders).
2. File delivery uses **stdin/stdout streaming** (`sh -c 'mkdir -p … && cat > file'` / `cat`),
   never `docker cp`/`kubectl cp` — streams compose transparently through any nesting depth and
   through kubectl. Docker and Kubernetes now share one `ExecStreamBridge`.
3. vsdbg install: try in-container download if the image has curl/wget; otherwise download
   locally (getvsdbg.sh, runtime id from the container's `uname -m`) and stream the tarball in
   via the same exec pipe. Requires local bash+tar (Linux/WSL/macOS).

## Consequences
- Works unchanged for plain docker, docker-in-docker devcontainers, and kubectl targets;
  `pipeTransport` nesting (`docker exec -i A docker exec -i B vsdbg`) passes the DAP stdio
  through both layers.
- vsdbg lives in the container's writable layer — recreating the stack removes it; the
  install prompt simply reappears.
- Devcontainer names are auto-generated by VS Code (e.g. `vsc-…` images, random names); users
  should pin a name (devcontainer.json `runArgs: ["--name", "…"]`) or update the setting after
  a rebuild.
