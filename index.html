    DEE Debugger for VS Code — User Guide¶

    Develop Critical Manufacturing MES DEE Actions in VS Code, against a running MES — with the full editor and a real debugger instead of the MES web UI's small code box.

    What it does:

    • Browse every DEE Action in the MES from a tree view.
    • Edit any action as a normal .cs file, with full C# IntelliSense.
    • Upload changes back to the MES — compile errors show inline in the editor.
    • Debug live — set breakpoints and step through your action while the MES host runs it. (The headline feature.)
    • Sync your whole action portfolio against a git-tracked customization project.

    It works whether the MES host runs as a local Docker container, inside a devcontainer, on a remote machine, in Kubernetes/OpenShift, or as a plain local process — and succeeds the "Critical Manufacturing DEE Explorer" Visual Studio add-in, rebuilt for VS Code.

    What is a DEE Action?

    A DEE Action (DEE = Dynamic Execution Engine) is a C# business rule stored in the MES database, not compiled into a customization DLL. Each attaches to an Action Group — an extension point like MaterialManagement.MaterialManagementOrchestration.CreateMaterial.Pre — and the host compiles and runs it on the fly when that operation happens. Because the code lives in the database, you'd normally edit it in the MES web UI; this extension gives you VS Code and a debugger instead.

    Development and test environments only

    The debugging and upload features are for dev/test only. Never attach a debugger to, or enable DEE debug mode on, a production MES. See the FAQ.

    Where things live in VS Code¶

    • Getting Started walkthrough — DEE Debugger: Open Getting Started (also Help → Welcome) walks through connect → authenticate → open → debug → sync with a button per step. The fastest first contact with the extension.
    • DEE Explorer — the tree view in the DEE Debugger icon on the Activity Bar (left edge of the window). Its title bar holds Refresh, New DEE Action…, Filter and Attach Debugger (plus VS Code's own Collapse All); everything else (Switch Environment, Sync, Expand All, Show Disabled Actions, Show Output Log, Collect Support Bundle, Open Getting Started) is under the … menu. On a row, hover for the inline actions and right-click for the full menu, including Open in MES UI.
    • Command Palette — press Ctrl+Shift+P (Cmd+Shift+P on macOS) and type "DEE Debugger" to see every command.
    • Status bar — the MES: <environment> item shows which environment you are connected to (and how many actions are in debug mode); click it to switch. Routine confirmations such as saved to MES also appear there briefly.
    • DEE Debugger output channel — View → Output, then pick DEE Debugger in the dropdown. This is the first place to look when something fails; see Troubleshooting.
